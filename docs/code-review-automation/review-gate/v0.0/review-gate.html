Team Runbook · open-code-review v1.12 기준

OCR 리뷰 게이트 운영 가이드

로컬에서는 Claude Code나 Codex로 먼저 리뷰하고, push가 되면 GitHub Actions에서 open-code-review(ocr)가 다시 리뷰합니다. critical·high 이슈가 나오면 Slack으로 알리고, 수정되기 전까지는 develop으로 머지할 수 없게 막습니다. 이 문서는 그 구성 방법과 실제 한 사이클을 따라가며 설명합니다.

대상 팀 개발자 · 저장소 관리자 소요 최초 설정 약 30분 필요 권한 저장소 Admin, Slack 앱 생성 권한

01 · 전체 구조

네 단계로 이루어진 리뷰 흐름

리뷰를 두 번 거칩니다. 로컬 리뷰는 개발자를 돕는 단계라 건너뛸 수 있고, CI 리뷰는 머지를 실제로 막는 단계입니다.

1 · 로컬

Claude Code / Codex로 사전 리뷰

/code-review, /simplify, Codex /review로 고친 뒤 머지를 준비합니다.

2 · GitHub Actions

push되면 ocr 자동 리뷰

feature/code-review에 push하면 게이트 리뷰가, develop에 push(머지)되면 사후 리뷰가 실행됩니다.

3 · Slack

critical·high만 알림

커밋 목록, push한 사람, 심각도별 건수, 주요 이슈 10건, 전체 리포트 링크를 채널로 보냅니다.

4 · GitHub Ruleset

통과해야 develop 머지

ocr-review 체크가 실패한 PR은 머지 버튼이 잠깁니다. 수정 후 다시 push해서 통과해야 풀립니다.

역할 분담: 리뷰는 찾고 알리기까지만

리뷰는 코드를 고치지 않고, 결함을 찾아 리포트하는 데서 끝납니다. 머지를 실제로 막는 것은 GitHub이고, 결함을 처리하는 것은 사람입니다.

역할담당하는 일하지 않는 일
리뷰ocr코드를 읽고 결함을 찾아 리포트 (result.json)코드 수정, 머지 결정
알림워크플로 Slack 단계critical·high가 있으면 채널에 리포트 요약 전송
머지 차단 신호워크플로 Gate 단계판정을 체크 상태(✓/✗)로 표시해 “머지하면 안 됨”을 알림실제 차단
머지 차단 집행GitHub Rulesetocr-review 체크가 ✗이면 머지 버튼을 잠금
결함 처리개발자리포트를 보고 수정하거나 오탐으로 판단
예외 승인팀 리드오탐일 때 bypass 권한으로 머지
  • 알림만 할지, 차단까지 할지는 Ruleset이 정합니다. ocr-review를 필수 체크로 두면 머지가 잠기고, 필수 체크에서 빼면 ✗ 표시와 Slack 알림만 남습니다. 리뷰 워크플로는 고치지 않아도 됩니다.
  • CI의 리뷰는 읽기 전용입니다. ocr에는 파일을 쓰는 도구가 없고, Claude Code 방식은 --allowedTools로 읽기 도구만 허용합니다.
  • 로컬 자동 수정 도구는 이 체계 밖입니다. /code-review --fix, /simplify, ocr 플러그인의 Claude Code 명령은 코드를 고칩니다. 개발자가 자기 PC에서 고르는 도구이고, CI 리뷰와는 섞이지 않습니다.

이 문서의 예시 사이클이 그대로 이 그림을 따라갑니다. 작업 브랜치는 개인 것이고, 게이트 역할은 feature/code-review가 맡습니다.

LOCAL개발자 PC

사전 리뷰 후 게이트 브랜치로 push

작업 브랜치에서 Claude Code나 Codex로 리뷰하고 수정합니다. 끝나면 feature/code-review에 머지해 push합니다. 이 단계의 결과는 머지 판단에 쓰이지 않습니다.

CI · gate modeGitHub Actions

develop 대비 브랜치 전체를 리뷰

push가 일어날 때마다 merge-base(develop, HEAD)..HEAD 전체를 다시 리뷰합니다. 이번 push의 커밋만 보면 앞선 push에서 지적된 이슈가 고쳐졌는지 알 수 없기 때문입니다. critical·high가 하나라도 있으면 ocr-review 체크가 실패합니다.

NOTIFYSlack 채널

막혔을 때만 알림

critical·high가 나왔거나 리뷰가 실패·미완료면 알림을 보냅니다. 통과 알림은 저장소 변수 OCR_SLACK_ON_PASS=true를 설정했을 때만 보냅니다.

GATEPull Request

체크가 통과해야 머지

Ruleset에서 ocr-review를 필수 체크로 지정합니다. 머지된 뒤에는 develop push로 사후 리뷰가 한 번 더 돌고, 이 리뷰는 알림만 보내고 아무것도 막지 않습니다.

  3. 저장소 파일권장

    팀 리뷰 규칙과 심각도 기준 커밋

    게이트는 critical·high 여부로 결정되므로 무엇이 critical·high인지 팀 기준을 규칙으로 적어 두는 것이 판정을 안정시키는 가장 좋은 방법입니다. merge_system_rule: true를 두면 ocr의 언어별 기본 규칙이 유지되고 그 위에 팀 규칙이 더해집니다.

    .opencodereview/rule.json
    {
  "exclude": ["**/generated/**", "docs/**", "**/*.min.js"],
  "rules": [
    {
      "path": "**/*",
      "rule": "심각도 기준: critical = 보안 취약점(인젝션, 인증/인가 우회, 시크릿 노출) 또는 데이터 손실. high = 운영 장애로 이어질 수 있는 버그(동시성, 트랜잭션 누락, NPE, 잘못된 에러 처리). 스타일과 네이밍은 low로 분류한다.",
      "merge_system_rule": true
    }
  ]
}

    적용될 규칙은 로컬에서 ocr rules check src/auth/attempts.py로 미리 확인할 수 있습니다.

  4. 저장소 파일GitHub Actions

    워크플로 파일을 develop에 커밋

    아래 파일을 .github/workflows/ocr-review.yml로 저장해 develop에 먼저 넣습니다. push 트리거 워크플로는 push된 커밋 안에 이 파일이 있어야 실행됩니다. develop에서 새로 만든 브랜치는 이 파일을 자동으로 물려받습니다.

    .github/workflows/ocr-review.yml
    name: OCR Review

on:
  push:
    branches:
      - feature/code-review   # 리뷰 게이트 브랜치. 모든 feature 브랜치에 적용하려면 'feature/**'
      - develop               # 머지 후 사후 리뷰 (리포트 전용, 머지를 막지 않음)

concurrency:
  group: ocr-review-${{ github.ref }}
  # 게이트 브랜치는 최신 커밋만 의미가 있으므로 이전 실행을 취소한다
  cancel-in-progress: ${{ github.ref_name != 'develop' }}

permissions:
  contents: read

env:
  BASE_BRANCH: develop

jobs:
  ocr-review:
    name: ocr-review          # Ruleset의 required status check 이름과 같아야 한다
    if: ${{ !github.event.deleted }}
    runs-on: ubuntu-latest
    timeout-minutes: 60
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0      # origin/develop 과의 merge-base 계산에 전체 히스토리가 필요

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install ocr
        env:
          OCR_VERSION: ${{ vars.OCR_VERSION || 'latest' }}
        run: npm install -g "@alibaba-group/open-code-review@${OCR_VERSION}"

      - name: Configure LLM
        env:
          OCR_PROVIDER: ${{ vars.OCR_PROVIDER || 'anthropic' }}
          OCR_MODEL: ${{ vars.OCR_MODEL }}
          OCR_API_KEY: ${{ secrets.OCR_API_KEY }}
          OCR_LANGUAGE: ${{ vars.OCR_LANGUAGE || 'Korean' }}
        run: |
          ocr config set provider "$OCR_PROVIDER"
          ocr config set model "$OCR_MODEL"
          ocr config set "providers.${OCR_PROVIDER}.api_key" "$OCR_API_KEY"
          ocr config set language "$OCR_LANGUAGE"
          ocr llm test

      - name: Resolve review range
        id: range
        env:
          BEFORE: ${{ github.event.before }}
          AFTER: ${{ github.sha }}
          REF_NAME: ${{ github.ref_name }}
        run: |
          if [[ "$REF_NAME" == "$BASE_BRANCH" ]]; then
            MODE=report
            # 이번 push로 develop에 들어온 변경만 리뷰
            if [[ "$BEFORE" =~ ^0+$ ]] || ! git cat-file -e "${BEFORE}^{commit}" 2>/dev/null; then
              FROM="${AFTER}^"
            else
              FROM="$BEFORE"
            fi
          else
            MODE=gate
            # 게이트는 매번 브랜치 전체(develop 대비)를 다시 본다.
            # push 단위로만 보면 이전 push에서 나온 미수정 이슈가 가려진다.
            FROM="origin/${BASE_BRANCH}"
          fi
          BASE_SHA=$(git merge-base "$FROM" "$AFTER")
          git log -n 100 --no-merges --format='- %h %s' "${BASE_SHA}..${AFTER}" > commits.md
          { echo "## 이번 리뷰에 포함된 커밋"; cat commits.md; } > background.md
          {
            echo "mode=$MODE"
            echo "from=$FROM"
            echo "base_sha=$BASE_SHA"
          } >> "$GITHUB_OUTPUT"

      - name: Run OCR review
        id: review
        env:
          FROM: ${{ steps.range.outputs.from }}
          AFTER: ${{ github.sha }}
          OCR_EFFORT: ${{ vars.OCR_EFFORT || 'medium' }}
          OCR_BUDGET: ${{ vars.OCR_MAX_TOKENS_BUDGET || '5000000' }}
        run: |
          set +e
          ocr review --from "$FROM" --to "$AFTER" \
            --format json --audience agent --output result.json \
            --background-file background.md \
            --effort "$OCR_EFFORT" \
            --max-tokens-budget "$OCR_BUDGET"
          echo "exit_code=$?" >> "$GITHUB_OUTPUT"

      - name: Evaluate result
        id: verdict
        env:
          EXIT_CODE: ${{ steps.review.outputs.exit_code }}
        run: |
          if [[ "$EXIT_CODE" != "0" || ! -s result.json ]]; then
            echo '{"status":"error","comments":[]}' > result.json
          fi
          STATUS=$(jq -r '.status // "unknown"' result.json)
          BLOCKERS=$(jq '[.comments[]? | select(.severity == "critical" or .severity == "high")] | length' result.json)
          if [[ "$STATUS" == "error" ]]; then
            VERDICT=error
          elif (( BLOCKERS > 0 )); then
            VERDICT=blocked
          elif [[ "$STATUS" =~ ^(failed|partial|completed_with_errors)$ ]]; then
            VERDICT=incomplete   # 일부 파일을 리뷰하지 못함: 통과로 치지 않는다
          else
            VERDICT=pass
          fi
          {
            echo "verdict=$VERDICT"
            echo "status=$STATUS"
            echo "blockers=$BLOCKERS"
          } >> "$GITHUB_OUTPUT"

      - name: Write report
        if: always() && steps.verdict.outcome == 'success'
        env:
          VERDICT: ${{ steps.verdict.outputs.verdict }}
          MODE: ${{ steps.range.outputs.mode }}
        run: |
          {
            echo "## OCR 리뷰 결과: \`$VERDICT\` (mode: $MODE)"
            echo
            echo "| critical | high | medium | low |"
            echo "|---:|---:|---:|---:|"
            jq -r '(.comments // []) as $c
              | ["critical", "high", "medium", "low"]
              | map(. as $s | [$c[] | select(.severity == $s)] | length | tostring)
              | "| " + join(" | ") + " |"' result.json
            echo
            jq -r '
              def rank: (.severity as $s | {"critical": 0, "high": 1, "medium": 2, "low": 3} | .[$s]) // 4;
              (.comments // [])
              | sort_by(rank)[]
              | "- **[\(.severity)]** `\(.path):\(.start_line)` (\(.category // "-")) \(.content | gsub("\\s+"; " "))"' result.json
          } >> "$GITHUB_STEP_SUMMARY"

      - name: Upload result
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: ocr-result-${{ github.run_id }}
          path: |
            result.json
            background.md
          if-no-files-found: ignore

      - name: Notify Slack
        if: always()
        continue-on-error: true   # Slack 장애가 게이트 결과를 바꾸지 않도록
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}
          SLACK_ON_PASS: ${{ vars.OCR_SLACK_ON_PASS || 'false' }}
          VERDICT: ${{ steps.verdict.outputs.verdict }}
          MODE: ${{ steps.range.outputs.mode }}
          BASE_SHA: ${{ steps.range.outputs.base_sha }}
          AFTER: ${{ github.sha }}
          REPO: ${{ github.repository }}
          BRANCH: ${{ github.ref_name }}
          ACTOR: ${{ github.actor }}
          SERVER: ${{ github.server_url }}
          RUN_ID: ${{ github.run_id }}
        run: |
          VERDICT="${VERDICT:-error}"
          if [[ "$VERDICT" == "pass" && "$SLACK_ON_PASS" != "true" ]]; then
            echo "통과: Slack 알림 생략"; exit 0
          fi
          if [[ -z "$SLACK_WEBHOOK_URL" ]]; then
            echo "::warning::SLACK_WEBHOOK_URL 시크릿이 없어 알림을 보내지 않았습니다"; exit 0
          fi
          [[ -s result.json ]] || echo '{"comments":[]}' > result.json
          [[ -f commits.md ]] || : > commits.md
          COMPARE="$SERVER/$REPO/compare/${BASE_SHA}...${AFTER}"
          [[ -n "$BASE_SHA" ]] || COMPARE="$SERVER/$REPO/commit/$AFTER"

          jq -n \
            --arg verdict "$VERDICT" --arg mode "$MODE" \
            --arg repo "$REPO" --arg branch "$BRANCH" --arg actor "$ACTOR" \
            --arg sha "${AFTER:0:7}" --arg compare "$COMPARE" \
            --arg run "$SERVER/$REPO/actions/runs/$RUN_ID" \
            --rawfile commits commits.md \
            --slurpfile res result.json '
            def esc: gsub("&"; "&amp;") | gsub("<"; "&lt;") | gsub(">"; "&gt;");
            def cnt($s): [.[] | select(.severity == $s)] | length;
            ($res[0].comments // []) as $c
            | ({
                pass: ":white_check_mark: 통과: critical/high 없음",
                blocked: ":rotating_light: critical/high 발견",
                incomplete: ":warning: 리뷰 미완료 (일부 파일 실패 또는 예산 초과)",
                error: ":x: 리뷰 실행 실패"
              } | .[$verdict]) as $headline
            | (if $mode == "report" then
                 (if $verdict == "pass" then "develop 사후 리뷰: 이상 없음"
                  else "이미 develop에 반영된 변경입니다. 수정 PR을 올려 주세요." end)
               else
                 (if $verdict == "pass" then "develop 머지 가능"
                  elif $verdict == "blocked" then "develop 머지 차단됨: 수정 후 다시 push 하세요"
                  else "develop 머지 차단됨: Actions에서 Re-run 하세요" end)
               end) as $impact
            | ([$c[] | select(.severity == "critical" or .severity == "high")]
                | sort_by(if .severity == "critical" then 0 else 1 end)
                | .[:10]
                | map("• *[\(.severity)]* `\(.path):\(.start_line)` \(.content | gsub("\\s+"; " ") | .[0:200] | esc)")
                | join("\n")) as $issues
            | {text: ([
                "*[OCR 코드 리뷰]* \($headline)",
                "> \($impact)",
                "*저장소* `\($repo)`   *브랜치* `\($branch)`   *푸시* \($actor | esc)",
                "*범위* <\($compare)|\($sha)>   critical \($c | cnt("critical")) · high \($c | cnt("high")) · medium \($c | cnt("medium")) · low \($c | cnt("low"))",
                (if ($commits | length) > 0 then "*커밋*\n```\n\($commits | .[0:1500] | esc)```" else empty end),
                (if $issues != "" then "*주요 이슈 (최대 10건)*\n\($issues)" else empty end),
                "<\($run)|전체 리포트와 제안 코드 보기>"
              ] | join("\n"))}' > payload.json

          curl -sS --fail -X POST -H 'Content-type: application/json' \
            --data @payload.json "$SLACK_WEBHOOK_URL"

      - name: Gate
        if: always()
        env:
          VERDICT: ${{ steps.verdict.outputs.verdict }}
          MODE: ${{ steps.range.outputs.mode }}
          BLOCKERS: ${{ steps.verdict.outputs.blockers }}
        run: |
          if [[ "$MODE" == "report" ]]; then
            echo "develop 사후 리뷰(리포트 전용). 결과: ${VERDICT:-error}"; exit 0
          fi
          case "${VERDICT:-error}" in
            pass)       echo "통과: critical/high 없음. develop 머지 가능" ;;
            blocked)    echo "::error::critical/high ${BLOCKERS}건. 수정 후 다시 push 하세요"; exit 1 ;;
            incomplete) echo "::error::리뷰가 끝까지 수행되지 않았습니다. Re-run 하세요"; exit 1 ;;
            *)          echo "::error::리뷰 실행 실패. 로그를 확인하세요"; exit 1 ;;
          esac
    이 워크플로가 하는 일 (단계별)
    • Resolve review range: develop이면 report 모드로 이번 push 범위(before..after)만, 그 외 브랜치는 gate 모드로 origin/develop 대비 전체를 리뷰합니다. 커밋 메시지는 --background-file로 넘겨 리뷰 맥락으로 씁니다.
    • Run OCR review: 결과를 result.json으로 받습니다. ocr는 이슈가 있어도 exit 0이므로 판정은 다음 단계에서 합니다.
    • Evaluate result: pass / blocked / incomplete / error 중 하나로 판정합니다 (판정 기준 참고).
    • Write report: 심각도별 건수와 전체 이슈 목록을 Actions 실행의 Summary 탭에 남깁니다.
    • Upload result: result.json(제안 코드 포함)을 아티팩트로 보관합니다.
    • Notify Slack: pass가 아니면 알림을 보냅니다. Slack 전송이 실패해도 게이트 결과는 바뀌지 않습니다.
    • Gate: gate 모드에서 pass가 아니면 job을 실패시켜 PR 머지를 막습니다.

06 · 판정 기준

워크플로가 결과를 판정하는 방법

ocr의 JSON 결과에서 status와 각 이슈의 severity(critical, high, medium, low 중 하나)를 읽어 판정합니다.

판정조건feature/code-review (gate)develop (report)Slack
passcritical·high 0건, 리뷰 정상 완료통과 · 머지 가능기록만OCR_SLACK_ON_PASS=true일 때만
blockedcritical 또는 high 1건 이상실패 · 머지 잠김알림만보냄
incompletestatus가 partial, failed, completed_with_errors (일부 파일 실패, 예산 초과)실패 · Re-run 필요알림만보냄
errorocr 비정상 종료 (설정 오류, API 키, 네트워크)실패알림만보냄

리뷰를 다 하지 못한 경우도 실패로 처리합니다. 일부 파일을 리뷰하지 못한 상태로 통과시키면 게이트를 둔 의미가 없기 때문입니다. 재실행해도 계속 incomplete라면 OCR_MAX_TOKENS_BUDGET을 늘리거나 PR을 더 작게 나누세요.

07 · 운영 가이드

운영하면서 정해 둘 것

오탐(잘못된 지적)이 게이트를 막을 때

  • 먼저 Re-run: LLM 리뷰는 실행할 때마다 결과가 조금씩 다릅니다. 근거가 약한 지적은 재실행하면 사라지기도 합니다.
  • 규칙 보강: 같은 오탐이 반복되면 .opencodereview/rule.json에 팀 기준을 적어 둡니다. 예: “내부 관리 API의 인가는 게이트웨이에서 처리하므로 지적하지 않는다”.
  • 예외 머지: 급할 때는 Ruleset bypass 권한자(팀 리드)가 머지합니다. PR 코멘트에 오탐 근거를 남기는 것을 팀 규칙으로 정하세요.

동시에 여러 명이 작업한다면

feature/code-review는 브랜치 하나를 같이 쓰기 때문에 한 번에 한 기능씩 리뷰하는 구조입니다. 여러 명이 동시에 쓰면 서로의 변경이 섞여서 남의 이슈 때문에 막힙니다. 병렬 작업이 많은 팀이라면 워크플로 트리거를 feature/**로 바꾸고, 각자 작업 브랜치에서 develop으로 바로 PR을 여는 방식을 권합니다. 나머지 설정(Ruleset, Slack, 판정)은 그대로 쓸 수 있습니다.

비용 관리

  • 게이트 브랜치에 push할 때마다 브랜치 전체를 다시 리뷰하므로, push 횟수만큼 비용이 듭니다. 로컬에서 충분히 고친 뒤 push하세요.
  • 같은 브랜치에 연달아 push하면 이전 실행은 자동 취소됩니다 (concurrency 설정).
  • develop 사후 리뷰가 필요 없다면 트리거에서 develop을 빼면 됩니다. 머지 1건당 리뷰가 1회 줄어듭니다.
  • OCR_EFFORT=low는 기본값보다 비용이 약 절반이고, 대신 찾아내는 이슈가 줄어듭니다.

main, release 브랜치로 확장

Ruleset 대상에 main, release/**를 추가하고, 해당 브랜치로 PR을 보내는 쪽 브랜치를 워크플로 트리거에 넣습니다. 기준 브랜치가 다르면 BASE_BRANCH를 브랜치별로 나눈 워크플로를 하나 더 두는 편이 단순합니다.

한계

  • ocr는 오탐을 줄이는 쪽으로 설계되어 있어 모든 결함을 찾지는 못합니다. 사람의 PR 리뷰를 대신하지 않습니다.
  • 변경 하나(diff)가 프롬프트 한도의 80%를 넘는 파일은 리뷰에서 빠집니다. 생성 파일, 대량 변경은 exclude로 빼세요.
  • 시크릿 마스킹 기능은 없습니다. 민감한 파일은 exclude에 넣으세요.
08 · 문제 해결

자주 생기는 문제

증상원인해결
PR 체크가 “Expected — Waiting for status”에서 멈춤PR head 브랜치가 트리거 목록에 없거나, 그 브랜치에 워크플로 파일이 없음브랜치 이름을 확인하고, 최신 develop을 머지해 워크플로 파일을 받아 옵니다.
Ruleset에서 ocr-review가 검색되지 않음체크가 한 번도 실행되지 않음설정 5단계(첫 실행)를 먼저 합니다. 이름을 직접 입력해도 됩니다.
Configure LLM 단계의 ocr llm test 실패API 키, 모델 ID, provider 이름 불일치Secrets와 Variables를 확인합니다. 로컬에서 ocr llm providers로 provider 이름을 확인할 수 있습니다.
