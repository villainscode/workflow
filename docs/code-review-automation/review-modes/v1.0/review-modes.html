Team Runbook · 실측 가이드 · open-code-review v1.12

API 키 방식과 Max 구독 방식 비교 실측

같은 커밋을 두 방식으로 동시에 리뷰해 품질, 속도, 비용을 직접 재고 팀 운영 방식을 정하기 위한 문서입니다. 하나는 ocr가 Anthropic API를 직접 호출하는 방식이고, 다른 하나는 ocr가 리뷰 대상과 규칙만 정하고 리뷰는 Max 구독의 Claude Code(claude -p)가 하는 방식입니다. 게이트, Slack 알림, 판정 구조는 OCR 리뷰 게이트 운영 가이드를 그대로 씁니다.

01 · 두 방식 한눈에

누가 LLM을 부르느냐의 차이

모델은 같습니다. 달라지는 것은 리뷰를 진행하는 프로그램과 요금을 내는 방식입니다.

A · API 키 방식

ocr review + Anthropic API

  1. ocr 리뷰 대상 파일 선별
  2. ocr 관련 파일 묶기, 파일별 규칙 매칭
  3. ocr 묶음마다 서브에이전트를 띄워 병렬 리뷰 (리뷰 전용 프롬프트와 도구)
  4. ocr 코멘트 위치 보정, 자기검증 필터로 오탐 제거
  5. ocr 고정 형식 result.json
인증
OCR_API_KEY (Claude Console)
요금
쓴 토큰만큼 과금. Sonnet 5.5 기준 리뷰 1회 약 $0.5~1.9 (추정)
B · Max 구독 방식

ocr delegate + claude -p

  1. ocr 리뷰 대상 파일 선별 (delegate preview)
  2. ocr 파일별 규칙 매칭 (delegate rule)
  3. Claude Code diff를 읽고 리뷰, 필요하면 저장소 탐색
  4. Claude Code JSON 스키마에 맞춰 결과 출력
  5. 워크플로 빠진 파일 검사 후 result.json으로 변환
인증
CLAUDE_CODE_OAUTH_TOKEN (claude setup-token)
요금
추가 과금 없음. Max 구독 사용 한도에서 차감

역할 분담: 리뷰는 찾고 알리기까지만

리뷰는 코드를 고치지 않고, 결함을 찾아 리포트하는 데서 끝납니다. 머지를 실제로 막는 것은 GitHub이고, 결함을 처리하는 것은 사람입니다.

역할담당하는 일하지 않는 일
리뷰ocr (A) 또는 Claude Code (B)코드를 읽고 결함을 찾아 리포트 (result.json)코드 수정, 머지 결정
알림워크플로 Slack 단계critical·high가 있으면 채널에 리포트 요약 전송
머지 차단 신호워크플로 Gate 단계판정을 체크 상태(✓/✗)로 표시해 “머지하면 안 됨”을 알림실제 차단
머지 차단 집행GitHub Rulesetocr-review 체크가 ✗이면 머지 버튼을 잠금
결함 처리개발자리포트를 보고 수정하거나 오탐으로 판단
예외 승인팀 리드오탐일 때 bypass 권한으로 머지
  • 알림만 할지, 차단까지 할지는 Ruleset이 정합니다. ocr-review를 필수 체크로 두면 머지가 잠기고, 필수 체크에서 빼면 ✗ 표시와 Slack 알림만 남습니다. 리뷰 워크플로는 고치지 않아도 됩니다.
  • CI의 리뷰는 읽기 전용입니다. ocr에는 파일을 쓰는 도구가 없고, Claude Code 방식은 --allowedTools로 읽기 도구만 허용합니다.
  • 로컬 자동 수정 도구는 이 체계 밖입니다. /code-review --fix, /simplify, ocr 플러그인의 Claude Code 명령은 코드를 고칩니다. 개발자가 자기 PC에서 고르는 도구이고, CI 리뷰와는 섞이지 않습니다.

03 · 각 방식의 장점

어느 쪽이 무엇을 잘하나

B · Max 구독 방식의 장점

  • 추가 비용이 없습니다. 이미 내고 있는 Max 구독 안에서 처리됩니다.
  • 준비가 간단합니다. API 결제 등록 없이 claude setup-token으로 만든 토큰 하나면 됩니다.
  • 저장소를 넓게 봅니다. 필요하면 Grep과 Read로 호출부, 설정, 테스트를 찾아봅니다. 저장소의 CLAUDE.md도 반영됩니다.
  • 작은 PR은 빠릅니다. 사전 테스트에서 2개 파일, 35줄 변경을 18~24초에 끝냈습니다.
  • 기준을 바로 고칠 수 있습니다. 심각도 기준과 보고 범위를 프롬프트 몇 줄로 조정합니다.

A · API 키 방식의 장점

  • 오탐이 적습니다. 위치 보정과 자기검증 필터가 코드로 들어가 있습니다.
  • 개인과 분리된 팀 자원입니다. 누구의 구독에도 묶이지 않습니다.
  • 비용을 통제하고 정확히 압니다. 실행마다 토큰과 상한이 남습니다.
  • 큰 PR에서 안정적입니다. 묶음마다 독립 컨텍스트로 병렬 처리하고, 끊기면 이어서 합니다.
  • 기록이 남습니다. 세션 비교와 재생으로 판단 근거를 추적합니다.

각 항목의 근거는 다음 절에 정리했습니다.

04 · API 키 방식의 핵심 이득

API 요금을 낼 때 얻는 것

영향이 큰 순서입니다. 게이트가 머지를 막는 구조에서는 1번이 가장 중요합니다.

  1. 오탐이 적어서 게이트를 믿을 수 있다

    게이트는 리뷰가 critical·high라고 판정하면 그대로 머지를 막을 뿐, 그 판정이 맞는지는 가리지 못합니다. 그래서 오탐은 곧 멀쩡한 PR의 차단이 되고, 오탐이 잦으면 팀이 예외 승인을 습관처럼 쓰게 되어 게이트가 무력해집니다. 반대로 리뷰가 놓친 결함은 게이트도 그대로 통과시킵니다. ocr는 같은 모델이라도 리뷰 과정을 코드로 강제해서 지적 수를 줄이고 정확도를 높입니다.

    같은 모델 (Claude Opus 4.6)ocrClaude Code 범용 리뷰

  2. 개인 구독과 분리된 팀 자원이다

    B 방식의 토큰은 claude setup-token을 실행한 사람의 구독에 묶입니다. Claude Code 문서도 여러 저장소에서 공유하는 시크릿에는 OAuth 토큰 대신 Console API 키를 쓰라고 안내합니다. API 키 방식은 담당자의 휴가, 퇴사, 사용 한도 소진과 상관없이 돌아가고, 팀원의 push가 늘어도 담당자의 Claude Code 작업량이 줄지 않습니다.

  3. 비용을 통제하고 정확히 안다

    --max-tokens-budget으로 실행 1회의 상한을 걸 수 있고, 결과마다 입력, 출력, 캐시 토큰이 기록되어 월 비용을 정확히 계산할 수 있습니다. Sonnet 5.5로 하루 2회 리뷰하면 월 약 $30~115 (기준 $57)로 추정됩니다. 구독 방식은 추가 비용은 없지만 한도를 얼마나 쓰는지 미리 알기 어렵습니다.

  4. 큰 PR에서도 안정적이다

    ocr는 관련 파일을 묶음으로 나눠 묶음마다 독립된 컨텍스트로 리뷰하고, 기본 8개를 동시에 처리합니다. 변경이 많아져도 한 대화에 모든 diff가 쌓이지 않습니다. 중간에 끊기면 --resume으로 이어서 합니다. B 방식은 한 세션에서 파일을 순서대로 보기 때문에 PR이 클수록 시간과 컨텍스트 부담이 커집니다.

  5. 기록이 남고 모델을 고를 수 있다

    ocr session compare로 이전 리뷰 대비 새로 생긴 이슈, 계속 남은 이슈, 해결된 이슈를 구분하고, ocr viewer로 모델이 어떤 파일을 읽고 왜 그렇게 판단했는지 다시 볼 수 있습니다. 필요하면 GPT, Qwen, Bedrock, 사내 모델로 바꿀 수 있습니다.

05 · 실측 준비

비교 워크플로 설치

한 번의 push나 수동 실행으로 두 방식이 같은 커밋을 동시에 리뷰하고, 마지막 job이 결과를 나란히 비교합니다. 실측 기간에는 머지를 막지 않습니다.

  1. A용

    API 키 등록

    Claude Console에서 API 키를 만들고 저장소 Secret OCR_API_KEY로 등록합니다. 실측 기간 비용을 묶어 두려면 Console에서 월 사용 한도를 낮게 걸어 두세요.

  2. B용

    구독 토큰 발급

    terminal (Max 구독자 본인 PC)
    claude setup-token

    출력된 토큰을 Secret CLAUDE_CODE_OAUTH_TOKEN으로 등록합니다. 이 토큰으로 실행되는 리뷰는 발급한 사람의 Max 사용 한도를 씁니다.

  3. 공통

    Variables 등록

    이름값설명
    OCR_MODELclaude-sonnet-5-5A 방식 모델
    CLAUDE_REVIEW_MODELclaude-sonnet-5-5B 방식 모델. 공정한 비교를 위해 A와 같게 둡니다.
    OCR_EFFORTmediumA 방식 리뷰 라운드 수
    OCR_VERSION1.12.12양쪽 ocr 버전 고정
  4. 저장소 파일

    비교 워크플로 커밋

    .github/workflows/ocr-compare.yml로 저장해 develop에 넣습니다. job 세 개가 돌아갑니다.

    job하는 일결과물
    review-apiocr review를 API 키로 실행result.json, 소요 시간
    review-maxocr delegate + claude -p를 구독으로 실행. 빠진 파일이 있으면 partialocr 형식으로 변환한 result.json, 원본 출력
    compare두 결과를 나란히 표로 정리하고 겹치는 지적을 찾음Summary 표, compare.json, 라벨링용 findings.csv

# 같은 커밋을 두 방식으로 동시에 리뷰해 결과와 비용을 비교한다.
# 실측 기간에는 머지를 막지 않는다 (리포트 전용).
on:
  push:
    branches:
      - feature/code-review
  workflow_dispatch:
    inputs:
      from:
        description: "비교 기준 (예: origin/develop)"
        default: "origin/develop"
      to:
        description: "리뷰 대상 커밋 (비우면 현재 커밋)"
        default: ""

concurrency:
  group: ocr-compare-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: read

env:
  BASE_BRANCH: develop
  REVIEW_LANGUAGE: Korean

jobs:
  review-api:
    name: review-api
    runs-on: ubuntu-latest
    timeout-minutes: 60
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Resolve review range
        id: range
        env:
          IN_FROM: ${{ inputs.from }}
          IN_TO: ${{ inputs.to }}
        run: |
          FROM="${IN_FROM:-origin/${BASE_BRANCH}}"
          TO="${IN_TO:-$GITHUB_SHA}"
          BASE_SHA=$(git merge-base "$FROM" "$TO")
          { echo "## 이번 리뷰에 포함된 커밋"; git log -n 100 --no-merges --format='- %h %s' "${BASE_SHA}..${TO}"; } > background.md
          { echo "from=$FROM"; echo "to=$TO"; } >> "$GITHUB_OUTPUT"

      - name: Install ocr
        env:
          OCR_VERSION: ${{ vars.OCR_VERSION || 'latest' }}
        run: npm install -g "@alibaba-group/open-code-review@${OCR_VERSION}"

      - name: Configure LLM
        env:
          OCR_MODEL: ${{ vars.OCR_MODEL || 'claude-sonnet-5-5' }}
          OCR_API_KEY: ${{ secrets.OCR_API_KEY }}
        run: |
          ocr config set provider anthropic
          ocr config set model "$OCR_MODEL"
          ocr config set providers.anthropic.api_key "$OCR_API_KEY"
          ocr config set language "$REVIEW_LANGUAGE"
          ocr llm test

      - name: Run ocr review
        env:
          FROM: ${{ steps.range.outputs.from }}
          TO: ${{ steps.range.outputs.to }}
          OCR_EFFORT: ${{ vars.OCR_EFFORT || 'medium' }}
        run: |
          set +e
          START=$(date +%s)
          ocr review --from "$FROM" --to "$TO" \
            --format json --audience agent --output result.json \
            --background-file background.md --effort "$OCR_EFFORT"
          CODE=$?
          echo "{\"exit_code\": $CODE, \"wall_seconds\": $(( $(date +%s) - START ))}" > run-meta.json
          [[ -s result.json ]] || echo '{"status":"error","comments":[]}' > result.json

      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: review-api
          path: |
            result.json
            run-meta.json

  review-max:
    name: review-max
    runs-on: ubuntu-latest
    timeout-minutes: 60
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Resolve review range
        id: range
        env:
          IN_FROM: ${{ inputs.from }}
          IN_TO: ${{ inputs.to }}
        run: |
          FROM="${IN_FROM:-origin/${BASE_BRANCH}}"
          TO="${IN_TO:-$GITHUB_SHA}"
          BASE_SHA=$(git merge-base "$FROM" "$TO")
          { echo "## 이번 리뷰에 포함된 커밋"; git log -n 100 --no-merges --format='- %h %s' "${BASE_SHA}..${TO}"; } > background.md
          { echo "from=$FROM"; echo "to=$TO"; } >> "$GITHUB_OUTPUT"

      - name: Install ocr and Claude Code
        env:
          OCR_VERSION: ${{ vars.OCR_VERSION || 'latest' }}
        run: npm install -g "@alibaba-group/open-code-review@${OCR_VERSION}" @anthropic-ai/claude-code

      - name: Run delegated review (Claude Code, Max subscription)
        env:
          CLAUDE_CODE_OAUTH_TOKEN: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          CLAUDE_MODEL: ${{ vars.CLAUDE_REVIEW_MODEL || 'claude-sonnet-5-5' }}
          FROM: ${{ steps.range.outputs.from }}
          TO: ${{ steps.range.outputs.to }}
        run: |
          set +e
          START=$(date +%s)
          # 리뷰 대상은 ocr가 정한다. Claude가 빠뜨린 파일은 아래 정규화 단계에서 잡아낸다.
          ocr delegate preview --from "$FROM" --to "$TO" -f json --background-file background.md > preview.json
          if [[ "$(jq '.reviewable_count // 0' preview.json)" == "0" ]]; then
            echo '{"status":"skipped","comments":[]}' > result.json
            echo "{\"exit_code\": 0, \"wall_seconds\": 0}" > run-meta.json
            exit 0
          fi

          cat > schema.json <<'SCHEMA'
          {"type":"object","additionalProperties":false,"required":["files_reviewed","comments"],"properties":{"files_reviewed":{"type":"array","items":{"type":"string"}},"comments":{"type":"array","items":{"type":"object","additionalProperties":false,"required":["path","start_line","end_line","severity","category","content"],"properties":{"path":{"type":"string"},"start_line":{"type":"integer"},"end_line":{"type":"integer"},"severity":{"type":"string","enum":["critical","high","medium","low"]},"category":{"type":"string","enum":["bug","security","performance","maintainability","test","style","documentation","other"]},"content":{"type":"string"},"existing_code":{"type":"string"},"suggestion_code":{"type":"string"}}}}}}
          SCHEMA

          cat > prompt.md <<PROMPT
          You are a code reviewer working in Open Code Review (OCR) delegation mode.
          Review the changes between ${FROM} and ${TO}. Do not modify any file.

          1. Run \`ocr delegate preview --from ${FROM} --to ${TO} -f json --background-file background.md\`.
             Review every path in reviewable_files and nothing else. Use merge_base from the output.
          2. Run \`ocr delegate rule <all reviewable paths>\` and treat each rule group as the checklist for its files.
          3. For each file, read its diff with \`git diff <merge_base>..${TO} -- <path>\`. Read surrounding code with Read, Grep and Glob when you need context.
          4. Report only defects in the changed code that you are confident about. Precision matters more than recall:
             a false alarm blocks a merge. Severity: critical = security vulnerability or data loss;
             high = bug likely to cause an incident; medium = context-dependent concern; low = minor.
          5. Line numbers must refer to the file at ${TO}. Write content in ${REVIEW_LANGUAGE}.
             Put the offending code in existing_code and a fix in suggestion_code when you have one.
          6. List every reviewed path in files_reviewed. Return an empty comments array when there is nothing to report.
          PROMPT

          claude -p --model "$CLAUDE_MODEL" \
            --output-format json \
            --json-schema "$(cat schema.json)" \
            --allowedTools "Bash(ocr delegate:*)" "Bash(git diff:*)" "Bash(git show:*)" "Read" "Grep" "Glob" \
            --permission-mode dontAsk \
            < prompt.md > claude-out.json
          CODE=$?
          echo "{\"exit_code\": $CODE, \"wall_seconds\": $(( $(date +%s) - START ))}" > run-meta.json

          # Claude Code 결과를 ocr의 result.json 형식으로 맞춘다 (판정/Slack/게이트 단계를 그대로 재사용하기 위해)
          if ! jq -e '.structured_output' claude-out.json > /dev/null 2>&1; then
            echo '{"status":"error","comments":[]}' > result.json
            exit 0
          fi
          jq -n --slurpfile o claude-out.json --slurpfile p preview.json '
            ($o[0]) as $out
            | ($out.structured_output) as $so
            | ($p[0].reviewable_files | map(.path)) as $expected
            | ($expected - ($so.files_reviewed // [])) as $missing
            | ($out.usage // {}) as $u
            | {
                status: (if $out.is_error then "error"
                         elif ($missing | length) > 0 then "partial"
                         else "success" end),
                llm: {provider: "claude-code-subscription", model: (($out.modelUsage // {}) | keys | first // "")},
                summary: {
                  files_reviewed: ($so.files_reviewed | length),
                  comments: ($so.comments | length),
                  input_tokens: (($u.input_tokens // 0) + ($u.cache_read_input_tokens // 0) + ($u.cache_creation_input_tokens // 0)),
                  output_tokens: ($u.output_tokens // 0),
                  cache_read_tokens: ($u.cache_read_input_tokens // 0),
                  cache_write_tokens: ($u.cache_creation_input_tokens // 0),
                  num_turns: ($out.num_turns // 0),
                  api_equivalent_cost_usd: ($out.total_cost_usd // 0)
                },
                missing_files: $missing,
                comments: $so.comments
              }' > result.json

        with:
          name: review-max

            result.json
            run-meta.json
            claude-out.json

        env:
          # Sonnet 5.5 API 단가 (USD / 1M tokens). 모델을 바꾸면 함께 수정한다.
          PRICE_IN: "2.00"
          PRICE_OUT: "10.00"
          PRICE_CACHE_READ: "0.20"
          PRICE_CACHE_WRITE: "2.50"
        run: |
          for m in api max; do
            [[ -s results/review-$m/result.json ]] || { mkdir -p results/review-$m; echo '{"status":"missing","comments":[]}' > results/review-$m/result.json; }
            [[ -s results/review-$m/run-meta.json ]] || echo '{"exit_code": -1, "wall_seconds": 0}' > results/review-$m/run-meta.json
          done

          jq -n \
            --slurpfile a results/review-api/result.json --slurpfile am results/review-api/run-meta.json \
            --slurpfile x results/review-max/result.json --slurpfile xm results/review-max/run-meta.json \
            --argjson pin "$PRICE_IN" --argjson pout "$PRICE_OUT" \
            --argjson pcr "$PRICE_CACHE_READ" --argjson pcw "$PRICE_CACHE_WRITE" '
            def cnt($s): [.comments[]? | select(.severity == $s)] | length;
            def cost: (.summary // {}) as $s
              | ((($s.input_tokens // 0) - ($s.cache_read_tokens // 0) - ($s.cache_write_tokens // 0)) * $pin
                 + ($s.cache_read_tokens // 0) * $pcr + ($s.cache_write_tokens // 0) * $pcw
                 + ($s.output_tokens // 0) * $pout) / 1000000;
            # 같은 파일에서 시작 줄이 3줄 이내면 같은 지적으로 본다

            ($a[0]) as $api | ($x[0]) as $max
            | {
                api: {status: $api.status, wall_seconds: $am[0].wall_seconds, files: ($api.summary.files_reviewed // 0),
                      critical: ($api | cnt("critical")), high: ($api | cnt("high")), medium: ($api | cnt("medium")), low: ($api | cnt("low")),
                      input_tokens: ($api.summary.input_tokens // 0), output_tokens: ($api.summary.output_tokens // 0),
                      cost_usd: ($api | cost), billed: "API 실제 과금"},
                max: {status: $max.status, wall_seconds: $xm[0].wall_seconds, files: ($max.summary.files_reviewed // 0),
                      critical: ($max | cnt("critical")), high: ($max | cnt("high")), medium: ($max | cnt("medium")), low: ($max | cnt("low")),
                      input_tokens: ($max.summary.input_tokens // 0), output_tokens: ($max.summary.output_tokens // 0),
                      cost_usd: ($max.summary.api_equivalent_cost_usd // 0), billed: "Max 구독 (API 환산값, 실제 과금 없음)",
                      missing_files: ($max.missing_files // [])},
                findings: (($api | tag2("api"; $max.comments // [])) + ($max | tag2("max"; $api.comments // [])))
              }' > compare.json

          {
            echo "## API vs Max 리뷰 비교"
            echo
            echo "| 항목 | API (ocr review) | Max (claude -p + delegate) |"
            echo "|---|---:|---:|"
            jq -r '
              def row($k; $label): "| \($label) | \(.api[$k]) | \(.max[$k]) |";
              row("status"; "상태"), row("wall_seconds"; "소요 시간(초)"), row("files"; "리뷰한 파일 수"),
              row("critical"; "critical"), row("high"; "high"), row("medium"; "medium"), row("low"; "low"),
              row("input_tokens"; "입력 토큰"), row("output_tokens"; "출력 토큰"),
              "| 비용 (USD) | \(.api.cost_usd * 1000 | round / 1000) | \(.max.cost_usd * 1000 | round / 1000) (환산) |"' compare.json
            echo
            jq -r '"- 양쪽 모두 지적 (±3줄): \([.findings[] | select(.mode == "api" and .matched)] | length)건",

                   "- Max에서만: \([.findings[] | select(.mode == "max" and (.matched | not))] | length)건",
                   (if (.max.missing_files | length) > 0 then "- ⚠️ Max가 빠뜨린 파일: \(.max.missing_files | join(", "))" else empty end)' compare.json
          } >> "$GITHUB_STEP_SUMMARY"

          # 사람이 정답/오탐을 표시할 라벨링 시트
          jq -r '["mode","severity","category","path","start_line","matched_other","content","label(TP/FP)"],
                 (.findings[] | [.mode, .severity, .category, .path, .start_line, .matched, (.content | gsub("\\s+"; " ")), ""])
                 | @csv' compare.json > findings.csv

      - uses: actions/upload-artifact@v4
        with:
          name: compare-${{ github.run_id }}
          path: |
            compare.json
            findings.csv

06 · 실측 진행과 판단

무엇을 재고 어떻게 정할까

진행 순서

  1. 표본 고르기: 지난 PR 10~20건을 고릅니다. 작은 것, 중간, 큰 것을 섞고, 머지 후 버그가 발견된 PR을 몇 건 넣으면 정답 확인이 쉽습니다.
  2. 실행: PR마다 위의 재현 명령으로 비교 워크플로를 돌립니다.
  3. 라벨링: compare 아티팩트의 findings.csv를 스프레드시트로 열고, 리뷰어 1~2명이 label 열에 TP(실제 결함) 또는 FP(오탐)를 적습니다. mode 열을 가리고 행 순서를 섞으면 방식에 대한 선입견을 줄일 수 있습니다.
  4. 흔들림 확인: 3~5건은 같은 커밋으로 2~3번 다시 실행해 결과가 얼마나 달라지는지 봅니다.
  5. 한도 확인: 실측 전후로 토큰 발급자의 Claude 사용량 화면을 확인해 B 방식이 한도를 얼마나 쓰는지 기록합니다.

08 · 운영 전환

결정한 방식으로 게이트 바꾸기

  • A로 정했다면: 첫 번째 가이드의 ocr-review.yml을 그대로 씁니다.
  • B로 정했다면: ocr-review.yml의 리뷰 단계만 아래로 바꿉니다. B의 결과를 ocr와 같은 형식으로 변환하므로 판정, 리포트, Slack, 게이트 단계는 수정하지 않아도 됩니다. 빠진 파일이 있으면 partial이 되어 게이트가 막습니다.
  • 실측이 끝나면: ocr-compare.yml의 push 트리거를 지우고 workflow_dispatch만 남겨 두면, 분기마다 품질을 다시 점검하는 데 쓸 수 있습니다.
ocr-review.yml 교체용 단계 (B 방식)
# ocr-review.yml(첫 번째 가이드의 게이트 워크플로)을 Max 구독 방식으로 바꾸는 방법
# 1. 'Install ocr' 단계를 아래 'Install ocr and Claude Code'로 바꾼다.
# 2. 'Configure LLM' 단계를 지운다 (API 키 불필요).
# 3. 'Run OCR review' 단계를 아래 같은 이름의 단계로 바꾼다 ('Resolve review range' 뒤 위치 유지).
# 4. 워크플로 최상단 env에 REVIEW_LANGUAGE: Korean 을 추가한다.
# Evaluate, Write report, Notify Slack, Gate 단계는 그대로 쓴다.

      - name: Install ocr and Claude Code
        env:
          OCR_VERSION: ${{ vars.OCR_VERSION || 'latest' }}
        run: npm install -g "@alibaba-group/open-code-review@${OCR_VERSION}" @anthropic-ai/claude-code

      - name: Run OCR review
        id: review
        env:
          CLAUDE_CODE_OAUTH_TOKEN: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          CLAUDE_MODEL: ${{ vars.CLAUDE_REVIEW_MODEL || 'claude-sonnet-5-5' }}
          FROM: ${{ steps.range.outputs.from }}
          TO: ${{ github.sha }}
        run: |
          set +e
          # 판정은 result.json의 status로 하므로 종료 코드는 항상 0으로 넘긴다
          echo "exit_code=0" >> "$GITHUB_OUTPUT"
          START=$(date +%s)
          # 리뷰 대상은 ocr가 정한다. Claude가 빠뜨린 파일은 아래 정규화 단계에서 잡아낸다.
          ocr delegate preview --from "$FROM" --to "$TO" -f json --background-file background.md > preview.json
          if [[ "$(jq '.reviewable_count // 0' preview.json)" == "0" ]]; then
            echo '{"status":"skipped","comments":[]}' > result.json
            echo "{\"exit_code\": 0, \"wall_seconds\": 0}" > run-meta.json
            exit 0
          fi

          cat > schema.json <<'SCHEMA'
          {"type":"object","additionalProperties":false,"required":["files_reviewed","comments"],"properties":{"files_reviewed":{"type":"array","items":{"type":"string"}},"comments":{"type":"array","items":{"type":"object","additionalProperties":false,"required":["path","start_line","end_line","severity","category","content"],"properties":{"path":{"type":"string"},"start_line":{"type":"integer"},"end_line":{"type":"integer"},"severity":{"type":"string","enum":["critical","high","medium","low"]},"category":{"type":"string","enum":["bug","security","performance","maintainability","test","style","documentation","other"]},"content":{"type":"string"},"existing_code":{"type":"string"},"suggestion_code":{"type":"string"}}}}}}
          SCHEMA

          cat > prompt.md <<PROMPT
          You are a code reviewer working in Open Code Review (OCR) delegation mode.
          Review the changes between ${FROM} and ${TO}. Do not modify any file.

          1. Run \`ocr delegate preview --from ${FROM} --to ${TO} -f json --background-file background.md\`.
             Review every path in reviewable_files and nothing else. Use merge_base from the output.
          2. Run \`ocr delegate rule <all reviewable paths>\` and treat each rule group as the checklist for its files.
          3. For each file, read its diff with \`git diff <merge_base>..${TO} -- <path>\`. Read surrounding code with Read, Grep and Glob when you need context.
          4. Report only defects in the changed code that you are confident about. Precision matters more than recall:
             a false alarm blocks a merge. Severity: critical = security vulnerability or data loss;
             high = bug likely to cause an incident; medium = context-dependent concern; low = minor.
          5. Line numbers must refer to the file at ${TO}. Write content in ${REVIEW_LANGUAGE}.
             Put the offending code in existing_code and a fix in suggestion_code when you have one.
          6. List every reviewed path in files_reviewed. Return an empty comments array when there is nothing to report.
          PROMPT

          claude -p --model "$CLAUDE_MODEL" \
            --output-format json \
            --json-schema "$(cat schema.json)" \
            --allowedTools "Bash(ocr delegate:*)" "Bash(git diff:*)" "Bash(git show:*)" "Read" "Grep" "Glob" \
            --permission-mode dontAsk \
            < prompt.md > claude-out.json
          CODE=$?
          echo "{\"exit_code\": $CODE, \"wall_seconds\": $(( $(date +%s) - START ))}" > run-meta.json

          if ! jq -e '.structured_output' claude-out.json > /dev/null 2>&1; then
            echo '{"status":"error","comments":[]}' > result.json
            exit 0
          fi
          jq -n --slurpfile o claude-out.json --slurpfile p preview.json '
            ($o[0]) as $out
            | ($out.structured_output) as $so
            | ($p[0].reviewable_files | map(.path)) as $expected
            | ($expected - ($so.files_reviewed // [])) as $missing
            | ($out.usage // {}) as $u
            | {
                status: (if $out.is_error then "error"
                         elif ($missing | length) > 0 then "partial"
                         else "success" end),
                llm: {provider: "claude-code-subscription", model: (($out.modelUsage // {}) | keys | first // "")},
                summary: {
                  files_reviewed: ($so.files_reviewed | length),
                  comments: ($so.comments | length),
                  input_tokens: (($u.input_tokens // 0) + ($u.cache_read_input_tokens // 0) + ($u.cache_creation_input_tokens // 0)),
                  output_tokens: ($u.output_tokens // 0),
                  cache_read_tokens: ($u.cache_read_input_tokens // 0),
                  cache_write_tokens: ($u.cache_creation_input_tokens // 0),
                  num_turns: ($out.num_turns // 0),
                  api_equivalent_cost_usd: ($out.total_cost_usd // 0)
                },
                missing_files: $missing,
                comments: $so.comments
              }' > result.json
