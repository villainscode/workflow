01범위

에이전트는 MCP 도구로 덱을 만들고, 사람은 화면에서 다음을 한다.

  • 요소를 클릭해 선택하고, 더블클릭으로 글자를 고친다(굵게·기울임·밑줄·링크·글자색).
  • 왼쪽 패널에서 슬라이드 목록을 보고 순서를 바꾸고, 오른쪽 속성 패널에서 크기·색·여백·간격을 바꾼다.
  • 고정 위치 요소를 끌어 옮기고 크기를 바꾼다. 흐름 배치 요소는 순서와 크기만 바꾼다.
  • 표의 열 너비를 끌어 바꾸고, 행·열을 넣고 뺀다.
  • 이미지를 올리고(파일 선택·끌어 놓기·붙여 넣기), 맞춤 방식과 자르기 위치를 고른다.
  • 되돌리기·다시 하기, 자동 저장, 다른 사람이 바꾼 슬라이드의 실시간 반영.
  • 발표 모드와 PDF 내보내기.

02결정 요약

기존 스택에 더하는 것만 적는다. 버전은 설치 시점의 최신 안정판을 쓰고, React 19와 함께 동작하는지 설치 직후 확인한다.

렌더링노드 트리를 React 요소로 그린다. innerHTML 금지허용 목록 밖은 그릴 방법이 없어 XSS가 구조적으로 막히고, 요소마다 data-eid를 붙이기 쉽다

03슬라이드 형식

캔버스는 1920×1080px로 고정한다. 화면 크기와 상관없이 같은 좌표계를 쓰고, 보여 줄 때만 축소한다.

덱 색인

{
  "v": 1,
  "title": "Platform팀 업무 소개",
  "order": ["cover", "agenda", "team"],
  "sections": { "s1": { "description": "팀 소개", "start": "team" } },
  "faces": { "ibm-plex-sans-kr": { "family": "IBM Plex Sans KR",
             "href": "https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+KR:wght@400;600;700" } },
  "palette": ["#1c2026", "#f7f7f4", "#0e6b57"]   // 속성 패널 색 견본
}

슬라이드 한 장

<section id="team" data-eid="team" style="background:#f7f7f4;padding:128px;display:flex;flex-direction:column;gap:48px">
  <h2 data-eid="e1" style="font-size:64px;font-weight:700;color:#1c2026">팀 소개</h2>
  <img data-eid="e2" src="asset:3f9a…" alt="콘솔 화면"
       style="position:absolute;left:896px;top:292px;width:896px;height:525px;object-fit:contain">
  <aside>발표자 노트</aside>
</section>

금지script, on* 속성, style 태그(글꼴은 덱 색인으로), 외부 url(), margin(간격은 gap·padding으로), z-index(그리는 순서 = 문서 순서)
요소 두 종류

position:absolute인 고정 요소는 끌어서 옮기고 크기를 바꾼다. 나머지 흐름 요소는 부모의 flex·grid가 위치를 정하므로 순서와 너비·높이만 바꾼다. 속성 패널에 「고정 위치로 전환」을 두어, 현재 화면상 상자를 계산해 left/top/width/height로 바꾼다.

04core: 파서·검증·직렬화

packages/core/slide/에 둔다. node:*를 쓰지 않는다는 기존 규칙을 지킨다.

// packages/core/slide/types.ts
export type Eid = string;
export type Style = Partial<Record<AllowedProp, string>>;

export type SlideNode =
  | { kind: "el"; eid: Eid; tag: BlockTag; style: Style; attrs: Attrs; children: SlideNode[] }
  | { kind: "text"; html: string }            // 인라인 마크만 들어 있는 텍스트 조각
  | { kind: "img"; eid: Eid; src: `asset:${string}`; alt: string; style: Style; crop?: Crop };

export type Slide = { id: string; root: SlideNode; notes: string };

export function parseSlide(html: string): { slide?: Slide; diagnostics: Diagnostic[] };
export function serializeSlide(slide: Slide): string;   // 항상 같은 속성 순서·형식으로 출력
export function validateStyle(prop: string, value: string): Diagnostic | null;  // css-tree로 값 문법 검사
export function applyOps(slide: Slide, ops: SlideOp[]): { slide: Slide; inverse: SlideOp[] };

export type Diagnostic = { line: number; col: number; code: string; message: string; fix?: string };
  • data-eid가 없는 요소에는 파싱할 때 붙이고 저장한다. 한 번 붙은 eid는 바뀌지 않는다. 에이전트의 부분 수정과 사람의 편집이 이 번호로 같은 요소를 가리킨다.
  • 검증 실패는 저장을 막고, fix에 가장 가까운 허용 표현을 적는다(예: margin-top:24px → 「부모 gap을 쓰세요」).
  • parse → serialize → parse 결과가 같아야 한다(왕복 안정성). 이 성질을 테스트로 묶는다.

편집 연산

사람과 에이전트가 같은 연산으로 슬라이드를 바꾼다. 연산은 eid로 대상을 가리켜, 다른 사람이 같은 슬라이드를 먼저 저장했어도 다시 적용할 수 있다.

export type SlideOp =
  | { t: "setText";   eid: Eid; html: string }                       // 인라인 마크만 허용
  | { t: "setStyle";  eid: Eid; set: Style; unset?: AllowedProp[] }
  | { t: "setAttr";   eid: Eid; name: "alt" | "href" | "src"; value: string }
  | { t: "insert";    parent: Eid; index: number; node: SlideNode }
  | { t: "remove";    eid: Eid }
  | { t: "move";      eid: Eid; parent: Eid; index: number }
  | { t: "toPinned";  eid: Eid; box: { left: number; top: number; width: number; height: number } }
  | { t: "tableCols"; eid: Eid; widths: number[] }                   // 합 100(%)
  | { t: "tableRow";  eid: Eid; at: number; op: "add" | "remove" }
  | { t: "tableCol";  eid: Eid; at: number; op: "add" | "remove" }
  | { t: "setNotes";  text: string };

05렌더링

<SlideCanvas scale={s}>            // 1920×1080 div, transform: scale(s), transform-origin: 0 0
  <SlideRenderer slide={slide} mode="edit" | "view" | "thumb" | "print" />
  <SelectionLayer />               // Moveable, 표 손잡이, 맞춤선. 캔버스와 같은 변환 안에 둔다
</SlideCanvas>
  • SlideRenderer는 노드를 재귀로 React 요소로 만든다. style 문자열이 아니라 검증된 객체를 React style로 넘긴다. 인라인 텍스트 조각만 core가 다시 검증한 뒤 dangerouslySetInnerHTML로 넣는다(허용 마크 5개뿐).
  • 썸네일·발표·인쇄·편집이 모두 이 컴포넌트를 쓴다. 화면마다 다르게 그려지는 문제가 없다.
  • Tailwind preflight가 h1 크기와 목록 기호를 지우므로, 캔버스 안에만 적용되는 기본 스타일 파일(slide-base.css)을 둔다. 형식의 태그 기본값(h1 96px·600, h2 64px, h3 44px, p 32px, 목록 기호·들여쓰기)을 여기서 정한다.
  • Shadow DOM은 쓰지 않는다. ProseMirror 선택 영역과 Moveable 좌표 계산이 shadow root에서 브라우저마다 다르게 동작한 사례가 있다. 스타일 격리는 위 기본 스타일 파일과 인라인 스타일로 충분하다.
  • 글꼴은 덱 색인의 Google Fonts 링크를 <head>에 넣는다. document.fonts.ready 뒤에 선택 상자를 다시 잰다.
  • asset: 주소는 그릴 때만 서명된 콘텐츠 도메인 주소로 바꾼다(§08).

06편집 상호작용

┌ 왼쪽 패널 ─────┐ ┌ 캔버스 ───────────────────────────┐ ┌ 속성 패널 ──────┐ │ 슬라이드 목록 │ │ 클릭: 선택 더블클릭: 글자 편집 │ │ 선택 요소 종류별 │ │ (dnd-kit 정렬) │ │ Esc: 부모 선택 Shift+클릭: 추가 선택 │ │ 입력 칸 │ │ 섹션 묶음 │ │ 화살표: 1px, Shift+화살표: 8px 이동 │ │ (허용 목록 기반) │ └────────────────┘ └────────────────────────────────────┘ └──────────────────┘

선택

  • 캔버스에서 pointerdown이 난 요소에서 위로 올라가며 가장 가까운 [data-eid]를 찾는다. 같은 자리를 다시 누르면 한 단계 안쪽 자식을 고른다(겹친 요소 고르기).
  • 선택 상태는 eid 배열로 둔다. 화면 좌표는 매번 getBoundingClientRect() / scale로 구한다. 좌표를 상태에 저장하지 않는다.
  • 여러 개 선택: Shift+클릭, 빈 곳에서 끌기(selecto).

이동·크기

  • react-moveable에 선택 요소를 넘긴다. 고정 요소는 draggable·resizable, 흐름 요소는 resizable만 켠다.
  • 맞춤선: 캔버스 가장자리, 여백선(128px), 형제 요소의 가장자리·가운데. 8px 단위 격자에 붙인다.
  • 끌기 중에는 DOM 스타일만 바꾸고, 놓을 때 setStyle 연산 하나로 확정한다. 되돌리기 한 번에 이동 하나가 취소된다.
  • 흐름 요소 순서는 속성 패널의 「앞으로·뒤로」 버튼과 같은 부모 안 끌어 놓기로 바꾼다(move 연산).

글자

  • 더블클릭한 텍스트 요소의 자식 자리에 Tiptap 편집기를 붙인다. 편집기는 그 요소의 계산된 글꼴·크기·줄 간격을 그대로 물려받는다.
  • 도구 막대: 굵게·기울임·밑줄·링크·글자색(덱 팔레트 견본 + 직접 입력). 글자 크기·글꼴은 블록 단위로만 속성 패널에서 바꾼다(형식이 span에 크기를 허용하지 않는다).
  • Esc 또는 바깥 클릭으로 끝내면 HTML을 core 검증기에 통과시켜 setText로 확정한다. Tiptap 자체 기록(History 확장)은 끄고 앱 되돌리기만 쓴다.
  • 글이 상자보다 길어지면 글자를 자동으로 줄이지 않는다. 상자 테두리를 경고색으로 바꾸고 「상자 높이 늘리기」 버튼을 보인다. 크기가 슬라이드마다 제각각이 되는 문제를 막는다.

07표 편집

  • 열 너비는 첫 행 칸의 width:N%로만 정한다. 선택된 표의 열 경계마다 손잡이를 캔버스 위 레이어에 그리고, 끌면 이웃 두 열의 비율만 주고받는다. 놓을 때 tableCols 연산 하나로 확정한다.
  • 행 높이는 내용과 칸 안쪽 여백으로 정해진다. 행 높이를 직접 끄는 손잡이는 두지 않고, 속성 패널에서 표 전체의 칸 여백을 바꾼다.
  • 칸 하나를 클릭하면 그 칸의 글자를 Tiptap(문단 하나, 인라인 마크만)으로 편집한다. Tab·Shift+Tab으로 다음·이전 칸으로 옮긴다.
  • 칸 오른쪽 클릭 메뉴: 위·아래 행 넣기, 왼쪽·오른쪽 열 넣기, 행·열 삭제. 열을 넣으면 너비를 균등하게 다시 나눈다.
  • 칸 병합(colspan·rowspan)은 형식에서 허용하지 않으므로 메뉴에도 두지 않는다.

08이미지 업로드

  1. 입력: 파일 선택, 캔버스에 끌어 놓기, 클립보드 붙여 넣기.
  2. 브라우저에서 긴 변 3840px 넘는 이미지는 줄이고(createImageBitmap + OffscreenCanvas), PNG·JPEG·WebP만 받는다. SVG는 받지 않는다(스크립트 위험).
  3. @noble/hashes로 sha256을 계산해 서버에 이미 있는지 먼저 묻는다. 없을 때만 기존 업로드 API로 R2에 올린다.
  4. 슬라이드에는 src="asset:<sha256>"만 저장한다. 서명 토큰이 12~24시간 뒤 만료되므로 서명 주소를 HTML에 저장하면 안 된다.
  5. 그릴 때 GET /api/w/:ws/assets/:sha/url로 서명 주소를 받는다. TanStack Query의 staleTime을 토큰 유효 시간보다 짧게 둔다.
  6. 자르기: object-fit과 object-position, 확대는 data-crop="배율 X% Y%"로 저장하고 렌더러가 transform: scale()로 그린다.

09상태·되돌리기

type EditorState = {
  deckId: string;
  slides: Record<string, { slide: Slide; rev: number; pending: SlideOp[] }>;
  current: string;              // 보고 있는 슬라이드 id
  selection: Eid[];
  undo: HistoryEntry[]; redo: HistoryEntry[];
};
type HistoryEntry = { slideId: string; ops: SlideOp[]; inverse: SlideOp[] };
  • applyOps가 역연산을 돌려준다. 되돌리기는 역연산을 새 연산으로 적용하고 저장한다. 서버 쪽에는 「되돌리기」라는 개념이 없다.
  • 되돌리기 기록은 슬라이드별이 아니라 편집기 전체에 하나. 다른 사람이 저장해 슬라이드가 바뀌면 그 슬라이드의 기록 중 적용할 수 없는 항목(eid가 사라진 것)은 지운다.
  • 단축키: Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, Cmd/Ctrl+D(복제), Delete, Cmd/Ctrl+C·V(요소 복사, eid는 새로 붙임).

충돌 처리

  • 화면은 연산을 모아 두었다가 마지막 편집 800ms 뒤에 한 번 보낸다. 슬라이드를 바꾸거나 창을 닫을 때는 바로 보낸다(visibilitychange, pagehide에서 fetch keepalive).
  • baseRev가 서버 rev와 다르면 서버는 연산을 최신 HTML에 다시 적용해 본다. 모든 대상 eid가 있으면 저장하고, 없으면 409와 최신 HTML을 돌려준다.
  • 409를 받으면 화면은 최신본을 받아 남은 연산을 다시 적용하고, 적용 못 한 연산은 「다른 사람이 지운 요소라 반영하지 못했다」고 알린다.
  • 저장이 끝나면 덱의 Durable Object에 { slideId, rev, by }를 알리고, 다른 접속자는 그 슬라이드만 다시 받는다. 접속자 표시(누가 어느 슬라이드에 있는지)도 같은 연결로 보낸다.
  • 글자 단위 동시 편집(Yjs 등)은 1차 범위에 넣지 않는다. 같은 슬라이드를 동시에 고치는 일이 드물다는 전제다. 필요해지면 슬라이드 단위 Yjs 문서 + Durable Object로 옮긴다.

11에이전트(MCP) 연동

packages/mcp-tools에 도구를 더한다. 로컬 stdio와 원격 MCP가 같은 코드를 쓰는 기존 구조를 따른다.

  • 모든 쓰기 도구는 core 검증 결과(Diagnostic[])를 그대로 돌려준다. 에이전트가 오류 위치와 fix를 보고 스스로 고친다.
  • 도구 설명에 형식 요약(§03 허용 목록, 캔버스 1920×1080, 여백 128px, 글자 최소 24px)을 넣는다. 에이전트가 처음부터 맞는 HTML을 쓰게 한다.
  • slide_revisions.source에 agent를 남겨, 사람이 수정본 목록에서 에이전트 변경을 구분하고 되돌릴 수 있게 한다.

12내보내기

  • 발표 모드: /w/:ws/decks/:id/present. 같은 SlideRenderer를 화면 크기에 맞춰 축소, 방향키·스페이스로 넘김, 발표자 노트 창.
  • PDF: Worker가 Browser Rendering으로 /present?print=1(서비스용 단기 토큰)을 열어 1920×1080 페이지로 인쇄하고 R2에 캐시한다. 키는 덱 rev 묶음의 해시. 인쇄 전에 document.fonts.ready와 모든 이미지 decode()를 기다린다.
  • PPTX: 2차 범위. 넣는다면 PptxGenJS로 고정 요소는 위치 그대로, 흐름 요소는 화면에서 잰 상자로 바꿔 내보낸다. 편집 가능한 PPTX를 완벽히 재현하려 하지 않는다.

13보안

  • 렌더러는 허용 목록 노드만 그린다. 서버는 저장 전에 같은 검증기를 다시 돌린다(화면 검증만 믿지 않는다).
  • 링크는 https:만, 그릴 때 rel="noopener noreferrer" target="_blank"를 붙인다.
  • 이미지는 기존 규칙대로 콘텐츠 도메인에서만 준다. 앱 CSP의 img-src에 콘텐츠 도메인을, style-src·font-src에 Google Fonts 두 도메인을 더한다.
  • 슬라이드 쓰기 API는 기존 Origin 검사와 쓰기 제한(분당 120회)을 그대로 받는다. 자동 저장 묶음(800ms) 덕에 보통 편집은 이 한도에 닿지 않는다.
  • viewer 역할은 편집기를 열 수 없고 발표 모드만 본다.

15테스트 기준

  • core(Vitest): 형식 예제 덱 전체의 왕복 안정성, 허용 목록 밖 태그·속성·CSS마다 진단 1건, 연산마다 적용 후 역연산 적용 시 원본과 같음.
  • Worker(Vitest + vitest-plugin): rev 충돌(같은 eid 수정, 지워진 eid 수정), 검증 실패 시 저장 안 됨, viewer 쓰기 거부, Origin 거부.
  • 화면(puppeteer): 더블클릭 → 한글 조합 입력(「한글 입력」을 IME 이벤트로) → Esc → 새로 고침 후 유지. 이미지 끌어 놓기. 열 손잡이 끌기 후 비율. 두 탭 동시 저장.
  • MCP: 잘못된 HTML을 slide_put하면 줄·칸·fix가 담긴 진단이 돌아오는지.

16하지 않는 것

  • 자유 HTML·CSS 편집 창. 형식을 벗어난 슬라이드가 생기고 검증기와 어긋난다. 필요하면 「HTML 보기」는 읽기 전용으로만 둔다.
  • 글이 넘칠 때 글자 크기 자동 축소. 슬라이드마다 크기가 달라지는 원인이 된다(§06).
  • z-index, margin, 그라데이션·그림자 같은 장식 속성. 형식이 허용하지 않고, 속성 패널에도 두지 않는다.
  • PPTX 원본 편집 재현. 원본은 항상 HTML 형식이고 PPTX는 내보내기 결과일 뿐이다.
